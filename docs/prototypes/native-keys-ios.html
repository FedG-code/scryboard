Scryboard keys on iOS

Four ways to draw the keyboard extension, each in light and dark, in typing, builder and grid mode, drawn at real size (1 pt = 1 px, 320 pt tall). One key is shown pressed with its pop-up. The last tab puts each candidate builder-key icon in its slot on the bottom row. Cards are drawn in CSS.

Today, for reference

What it is: the build on the phone since 2026-09-25. 42 pt keys on a 52 pt pitch, 5 pt corners, 1 pt hard shadow at 25 %, letters SF 20 pt regular, function labels 15 pt, symbols 17 pt. Letter keys are systemBackground, so pure black in dark mode; function keys systemFill; the search key is grey like the other function keys.

Reads as off: letters a size too small and too heavy, pure-black dark keys where the system uses mid grey, no blue on the search key, rows a shade too tight.

A · System replica

Copies: KeyboardKit's measured values: backdrop #D1D3D9 / #2B2B2B, white and #ABB1BA keys (#6B6B6B / #474747 dark), 42 pt keys on a 54 pt pitch, 6 pt gaps, 5 pt corners, a 1 pt unblurred bottom edge (30 % light, 70 % dark), lowercase letters in SF light at about 24 pt, 16 pt function labels, 20 pt light SF Symbols, system-blue search key, the key pop-up, and press states that swap the two greys.

Changes from the system: the search key keeps the return symbol (the system would write the word). The pill and chips take the same greys so nothing in the extension looks foreign.

Cost in UIKit: low. Constants in KeyButton and KeyboardView (pitch, font, weights, dark colours as fixed asset colours rather than systemBackground), a blue fill for .search, and a pop-up view shown on touch-down for letter keys, about a day with the pop-up. The root view must stay clear on iOS 26 so the system's rounded backdrop shows.

B · iOS 26 glass

Copies: the metrics of A. Changes: translucent keys with a 1 pt top highlight and a soft 2 pt shadow, 8 pt corners, the chat blurred through the backdrop and the keys, a glass tint on the search key and the capsule. This is a reading of Liquid Glass, not what the system keyboard does: Apple's Materials guidance keeps glass for floating controls and the iOS 26 keyboard stayed a solid surface with rounded outer corners.

Cost in UIKit: medium. UIVisualEffectView under the keyboard and per key (or one blur with masked key shapes), gradient highlight layers, and a memory check: blur views in an extension cost real memory against the ceiling, and the host content under a keyboard extension is not visible to it, so the blur can only sample the extension's own backdrop. In practice the glass would blur a flat colour, which is why the mock-up's effect cannot be reproduced faithfully.

C · Quiet flat

Copies: the metrics, greys, type and blue search key of A. Changes: no shadow, 6 pt corners, function grey a touch lighter so the key edges still separate without the edge line; dark keys a step darker.

Cost in UIKit: lowest. The same constants as A with the shadow layer removed; no pop-up needed, though one could be added later. The risk is reading as a web page: the hard bottom edge is one of the strongest native cues.

Builder key in place

The bottom row of option A at real size, with each candidate in the builder slot (outlined). SF Symbols cannot be embedded in a web page, so the glyphs are hand-drawn approximations of the named symbols; on the phone the text labels render in the real SF font. Sliders are what ships today.

Research pick: shrinking lines (line.3.horizontal.decrease) first, the word "Filter" second.
