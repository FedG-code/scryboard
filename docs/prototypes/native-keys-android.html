Scryboard keys on Android

Three ways to draw the planned Android keyboard next to Gboard on a Pixel, each in light and dark, in typing, builder and grid mode, at real size (1 dp = 1 px, 320 dp tall). One key is shown pressed with Gboard's round pop-up. The last tab puts each candidate builder-key icon in its slot, using the real Material Symbols font. Cards are drawn in CSS.

A · Gboard default, Material 3

Copies: Gboard's non-dynamic theme as described since its 2021 redesign and the February 2025 update: neutral grey backdrop, white letter keys one tone lighter, one shared darker tone for every non-letter key, no shadows or outlines, 8 dp corners, 46 dp keys on a 54 dp pitch with 6 dp gaps, Roboto 22 sp regular letters (Gboard uses Google Sans Text), Material Symbols at 24 dp, the enter key a pill in Google blue carrying the search action's icon, a round pop-up on press, a 10 % state layer.

Changes: the plane key says ?123 as Gboard's does; the space bar stays unlabelled where Gboard shows the language; the enter key shows a magnifier, which is what Android draws for a search action, instead of the return symbol.

Cost in Android views: low. One key view with a rounded-rect background drawable per key class, a ripple or colour swap for the state layer, a popup window for the preview. Colours as fixed resources for light and night.

B · Material You dynamic colour

Copies: the geometry and type of A. Changes: every colour is a Material 3 role taken from the system palette: backdrop surfaceContainer, letter keys surfaceContainerLowest (light) or surfaceContainerHigh (dark), function keys, chips and the Back capsule secondaryContainer, the enter key and Search primary, the pop-up secondaryContainer. The baseline purple stands in for the wallpaper's hue; on a phone the keyboard takes whatever colour the wallpaper gives it, which is the trait users read as "Pixel".

Cost: low to medium. The same views as A reading system_accent and system_neutral resources (API 31) or the role resources (API 34) through DynamicColors.wrapContextIfAvailable, with A's fixed palette as the fallback below Android 12.

C · Borderless

Copies: Gboard with its "key borders" setting off: letters sit straight on the backdrop, only the space bar and the enter key keep a pill, function glyphs are just glyphs. Material You roles as in B. Changes: chips lose their fill and keep a 1 dp outline as M3 outlined chips; the pressed state is the 10 % state layer alone, which is all that separates keys, so the pop-up matters more.

Cost: lowest to draw, but the hit targets are invisible, so a first-time user gets less guidance; Gboard ships this as an option, not the default.

Builder key in place

The bottom row of option A at real size, with each candidate in the builder slot (outlined). These are the real Material Symbols, outlined style, 24 dp. tune is the Android twin of the sliders that ship on iOS today.
